MediaBar

A native macOS application that turns the MacBook notch into an ambient media controller. Consolidates Spotify, Apple Music, YouTube, Audible, Podcasts, and any other "Now Playing" source into a single pill that surfaces track info, artwork, and controls without breaking focus. Overview

MediaBar is a macOS application that turns the notch on modern MacBooks into a unified media surface. It detects whatever is currently playing — Spotify, Apple Music, YouTube in any browser, Audible, Podcasts, Apple TV — and exposes the track, artwork, and controls in a pill that sits flush with the hardware notch.

The notch is otherwise dead screen real estate. macOS's own "Now Playing" widget lives one click deep in Control Center, only handles a subset of apps cleanly, and disappears the moment you focus elsewhere. MediaBar makes the same information ambient — visible at a glance, expandable on hover, and capable of controlling any source from one place.

Why I Made This

I move between Spotify, YouTube in Safari, Audible, and the occasional podcast throughout the day, and macOS treats each of those as a separate problem. The Now Playing widget covers some of them inconsistently, Audible can only really be paused from inside Audible, and a YouTube tab playing in the background is invisible unless you remember which window it's in.

I wanted one persistent surface that reflected whatever was actually playing, regardless of source, and let me pause, skip, or scrub without context-switching. The notch was the right home for it: it's already there, it's already a focal point, and it's visually distinct enough to not feel like another menu bar widget competing for attention.

User Experience

The pill sits in the notch area as a thin black bar that blends with the hardware notch itself. In its collapsed state only two elements are visible — a small album thumbnail on the left and an animated equalizer on the right that pulses while audio is playing. The rest of the pill stays out of the way.

Hovering reveals the compact dropdown: track title, artist, artwork, and inline playback controls (previous, play/pause, next) with a scrubbable progress bar underneath. Double-clicking the artwork opens the expanded view, which fills out the full pill with the album cover, track info, ±30 second skip buttons (useful for Audible and podcasts), and timestamps.

Right-clicking anywhere on the pill brings up a context menu with display toggles (artwork, now-playing animation, song name, always-visible mode) and a source picker that lets the user manually pin the pill to Spotify, Apple Music, Audible, or Podcasts. The pin persists across launches; auto-switch otherwise follows whichever source most recently started playing and pauses the previous one.

Key Features

  • Multi-source detection — Spotify, Apple Music, Audible, Podcasts, YouTube (via any major browser including Safari Web Apps), Apple TV, and any other system "Now Playing" source. Each source is routed through the appropriate control path: AppleScript for Spotify and Apple Music, the private MediaRemote framework for everything else, AppleScript JavaScript injection for live browser video position.
  • Notch-aware three-state layout — an idle pill that sits flush with the notch, a compact dropdown for hovering, and a full expanded view with artwork and extended controls. All three states centre around the actual notch position rather than a fixed screen coordinate.
  • Auto-source switching with manual override — when something starts playing in another app, the pill follows automatically and pauses the previous source so two streams never overlap. Users can pin to a specific source via the right-click menu or cycle by double-clicking the artwork, with the choice persisting in UserDefaults.
  • Live YouTube position tracking — MediaSession's positionState only fires on play/pause/seek, so during steady-state playback the system's reported position goes stale. MediaBar reads the actual <video>.currentTime via AppleScript JavaScript injection on a 2.5-second background poll, scans for the playing video element to handle YouTube Shorts (where several <video> tags share the DOM), and re-anchors the displayed position whenever it drifts.
  • Catalyst app fallback for Audible and Podcasts — these apps expose minimal AppleScript surfaces and ignore play commands when nothing's queued. MediaBar walks the accessibility tree looking for a play button, falls back to a calculated coordinate click on the first library tile, and finally to a Tab+Return keystroke — all gated behind a one-time accessibility-permission explainer.
  • Per-source artwork pipeline — Apple Music artwork is pulled from the current track via AppleScript and cached as PNG; Spotify artwork comes through its scripting bridge; system Now Playing artwork is fetched from MediaRemote with retry-and-backoff for sources like YouTube where thumbnails aren't immediately available after a play event.
  • Wall-clock position projection — the displayed playback position is computed as (anchor + (now - anchorTime)) rather than incremented from a stored counter. Timer jitter never accumulates, and unrelated source updates can't drag the bar backwards.
  • Cold-launch focus protection — when a source needs to be launched (switching to Spotify when it isn't running, for instance), the launch uses activates = false, hides = true, and the running app is hidden again at four staggered intervals so Electron apps that ignore the initial hide flag still stay out of the user's way.

Technical Architecture

Built as an Xcode project targeting macOS 13+. SwiftUI handles all view content, AppKit handles the notch window and global event monitors, Combine drives state propagation, and a vendored Perl adapter bridges access to MediaRemote on macOS versions where direct framework access is gated.

MediaBar ├── App/ │ └── MediaBarApp.swift — Entry point, NSApplication setup ├── Models/ │ ├── MediaSource.swift — Source enum, MediaSourceProtocol, position projection │ ├── MediaItem.swift — Track metadata (title, artist, artwork, position) │ └── PlaybackState.swift — ObservableObject for view bindings ├── Services/ │ ├── MediaManager.swift — Source coordination, auto-switching, anchor logic │ ├── SpotifyService.swift — AppleScript polling │ ├── AppleMusicService.swift — AppleScript polling, artwork extraction │ ├── SystemMediaService.swift — MediaRemote stream parsing, browser JS injection │ └── ArtworkService.swift — Async image loading and caching ├── Notch/ │ ├── NotchWindowController.swift — NSWindow lifecycle, three-state transitions │ └── NotchHoverDetector.swift — Global event monitors (hover, right-click, double-click) ├── Views/ │ ├── NotchIdleView.swift — Collapsed pill with equalizer │ ├── NotchDropdownView.swift — Compact hover view │ └── ExpandedMediaView.swift — Full controls, scrubbable progress └── Resources/ └── MediaRemoteAdapter/ ├── mediaremote-adapter.pl — Vendored MediaRemote bridge (Perl subprocess) └── MediaRemoteAdapter.framework

The MediaManager is the central coordinator: it owns the per-source services, observes their state via callbacks, and runs the active-source selection logic. Position is anchored as a wall-clock projection rather than a counter so timer jitter never accumulates and unrelated source polls can't pull the bar backwards. SystemMediaService spawns the vendored Perl adapter as a subprocess and parses its line-delimited JSON output, which lets MediaBar read MediaRemote on macOS 15.4+ where direct in-process access was gated by Apple. Artwork lives behind an async pipeline so cold thumbnails (typically YouTube videos that haven't published their cover yet) retry with backoff instead of failing hard.

Reflections

This project pushed deeper into macOS's private APIs and inter-process scripting than I expected. MediaRemote is the only unified pipeline for "Now Playing" data across apps and browsers, but Apple closed direct access in macOS 15.4. The workaround was to vendor an existing Perl adapter that holds the right entitlements, run it as a subprocess, and parse its JSON output. That kind of IPC inside a native Mac app isn't a typical Cocoa pattern, but it ended up being one of the more interesting parts to build.

The harder problem was position accuracy for YouTube. Spotify and Apple Music both expose their player position cleanly through AppleScript, but a YouTube tab is hidden behind several layers: the browser owns the page, the page owns the MediaSession API, and MediaSession only updates its position on user actions. The fix was to read the live <video> element's currentTime directly via AppleScript JavaScript injection on a background poll, with extra logic to find the actually-playing video element on YouTube Shorts (which keeps several <video> tags alive simultaneously). It works in regular Safari and Chromium-family browsers, with graceful degradation in Safari Web Apps that sandbox JavaScript injection out entirely.

The notch itself was the design constraint that shaped everything else. It's already a focal point, but treated as visual debris by every other app. Making the pill sit flush with the notch's curvature, hide and reveal smoothly on hover, and stay out of the way at every other moment took a lot of restraint with motion and chrome. Like Battery Hub, MediaBar does one thing — but it does it everywhere the user might be listening.
